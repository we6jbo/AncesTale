# Session bridge v0.3.0
Build with Qt 6 Widgets, Network, Multimedia and OpenSSL Crypto. Configure Qt Creator build directory under the project build/ folder. Existing signature checks and manual Vibe launcher are preserved. The session tab reads a fixed LAN HTTP endpoint; no inbound listener, no SSH, no shell launch. The desktop requires the remote state to exactly match the local approved state and checks the local music SHA-256 before playback. HTTP itself is not authenticated: use only a trusted LAN; browser delivery remains unauthenticated. It cannot verify actual browser playback; the label reports requested website track only. Clocks must be synchronized; polling can lag by a few seconds and browser autoplay requires user gesture. No track was provided. Original generated chime is bundled.

Use session/VIBE.md through Prepare Mistral Vibe Research. For a future date, create a local reviewed index CSV with file,title,license,source_url,reviewed and copy identical track into Music/ on T14 and music/ on Pi. Run sessionctl prepare as documented; it rejects past starts. Deploy the web controller to the existing game page only after checking URL mapping. Both clients must stay running. No scheduler is installed. At 15:22 Vibe must be active to write the draft. No actual Pi page or installed Qt kit was available for testing. Use .session-local/ for private state and drafts; never publish it.
