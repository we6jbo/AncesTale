# AncesTale 0.7.3 recovery candidate

Owner-approved release candidate. No Git operations, no live Pi or T14 modifications made by ChatGPT. The archive includes a focused local source patch against AncesTale(3).zip, nine prepared fallback chapters, and nine emergency speeches. It does not include the private Pedigree template, signed files, music binaries, player registry, credentials or Git metadata.

## Review before installing

1. Open `fallback/index.html` locally for an isolated visual preview (no audio, network reports, or live deployment). Default preview day is November 21; append `?preview=1&day=2026-11-22` etc. to select other dates. The artwork is original programmatic SVG; it is a richer illustrated prototype, not photorealistic production art.
2. Read `fallback/daily-speeches.md`; these are prospective drafts, not accounts of completed games. Birth fields came from the archived signed SQLite record; the signatures were verified against the supplied public key but do not independently prove genealogy claims. Verify source pointers and pronunciation before public presentation.
3. Close the GUI. Only after you approve the candidate, run `python3 install-review.py --apply` from the extracted package. It validates the local root, checks original files against the uploaded baseline, verifies pinned certificate and signatures, and creates in-project backups prior to writes. It does not stage, commit or push.
4. Compile with `cmake -S . -B build/Desktop_Debug && cmake --build build/Desktop_Debug -j4` inside the exact AncesTale project. Qt compilation has not been verified here. Do not deploy until build and UI smoke test pass.

## Scope / limitations

The fallback is a small prewritten illustrated adventure, four discoveries each day, not a dynamic AI-built world. Automatic rails advances within the prepared chapter, not arbitrary branches. The next-branch button appears when 3 of 4 discoveries are reached and checks whether the live page has changed. It does not pretend new content exists if no new branch is available. Local browser storage preserves same-day fallback progress, not cross-browser or server-side saved game state. Actual user-controlled live story navigation, richer high-quality art, server-side persistence, long-duration synchronized multi-track desktop playback, and WordPress media publishing require further live tests/implementation. Fallback browser uses Intro / middle / outro with silence between; the existing editable four-part timing stays in the live Music tab. It does not implement live 3/4 scheduling or guarantee sound without user gesture. Browser autoplay can reject sound; Begin is the unlock action. No extra enable-sound button. Cue IDs are stored in browser localStorage per day; clearing it can allow repeats. Original notes and licenses remain immutable. Fallback track durations were measured with ffprobe on the uploaded audio; remote filenames and licenses must be rechecked before actual use. Tracks marked once-ever or sequential-only are excluded from the prepared fallback. No independent music license audit was performed. Do not automatically use media unless rights and file identity are verified.

The desktop fix replaces infinite looping with a one-play attempt per session while running, chooses current system default audio device, accepts sessions up to 6.5 hours in the existing single-track protocol, and reads the newest valid date/session draft. It does not implement full synchronized multi-track desktop cue handling. The Qt source changes and network integration require on-device verification. Browser UI script syntax has been checked; automated Chromium navigation was blocked by this environment, so visual/interaction results are not claimed.
